# 旅行相册

两人共用的网页版旅行相册：网页放在 GitHub Pages，照片和相册数据放在私有的腾讯云 COS 存储桶里。依据 `gcy2016/AI_Corp` issue #8《旅行相册 PRD 2.0》、#13《PRD 补充版》及其后的用户决定实现。

> 仓库名称约定：本仓库（网页代码，公开）与原 OurTrip 仓库（映射源文件，私有）互换名称——本仓库改名为 **OurTrip**，原 OurTrip 改名为 **workspace-9**。下文均按互换后的名称书写。

- 正式地址（开启 Pages 后）：`https://gcy2016.github.io/OurTrip/`
- 演示模式（不连接云端，数据只存在当前浏览器里，密码 `demo1234`）：`https://gcy2016.github.io/OurTrip/?demo=1`
- 部署步骤：[`docs/部署说明.md`](docs/部署说明.md)

## 功能概览

| 功能 | 说明 |
|---|---|
| 固定区域 | 一级 34 个、二级 333 个，完全来自 `data/region-map-anon.js`（与私有仓库 `workspace-9/private/region-map-anon.js` 相同，映射有变更时需同步复制）；名称见下一行。没有二级区域的一级区域（A01、A02、A09、A22、A32、A33、A34）点进去直接是内容。 |
| 区域名称 | 真实名称不进公开仓库：维护工具在浏览器里解密私有映射文件，计算简称（不超过 4 个字，去掉省/市/自治区/自治州/地区/盟和民族名；重名时加回“省/市/州”，兴安盟保留原名），上传到存储桶 `meta/region-names.json`；网页登录后读取，读不到时显示编号。二级区域名称不带一级区域前缀，方框里用大字号（最大为方框高度的 1/4，越长越小，最多两行）。 |
| 区域显示 | 代表图片、默认颜色在 `js/region-display.js` 中维护。用户在网页上选的照片与仓库配置的代表图片“谁后设置谁生效”，可以互相替换；生效的一方失效时显示另一方，都没有时显示默认蓝色。 |
| 自动点亮 | 加载时由 `album.json` 计算：某区域下任意末级框里有照片、文字备注或地点，该区域及其一级区域就点亮；框标题和框结构不算。 |
| 点亮日期 | 精确到天。二级区域（及无二级的一级区域）第一次点亮时记录当天；旧数据取该区域最早的照片上传日期。可在区域页“修改点亮时间”；取消点亮后清空，再次点亮按新日期记录；页面加载不会覆盖用户改过的日期。有二级区域的一级区域取下属最早日期，不能单独修改。区域方框上显示日期。 |
| 地图 | 首页“地图”入口。横向铺满屏幕（竖屏时整页旋转 90°，不锁定方向、不提示旋转）。只读，一级区域按首页点亮状态着色，点击显示名称和点亮日期（未点亮显示“未点亮”）。台湾作为普通区域直接显示；南海诸岛放在台湾右侧的小框里，亮暗跟随所属区域，主图只按大陆和近岸岛屿取范围（不为南海诸岛缩小大陆）；香港、澳门在原位置画小圆点，引线连到台湾右侧、南海诸岛小框左侧的名称标注（引线从台湾下方绕过），点击标注显示该地的点亮日期或“未点亮”，亮暗跟随首页（用户决定，与补充版 2.4 前置条件中“港澳只保留小点、共用热区”的写法不同）。不显示九段线。地图由维护工具清洗后上传到 `meta/china-map.json`（只保留坐标路径）。 |
| 时间线 | 首页“时间线”入口。只读竖向时间轴，倒序：最新点亮的在最上面，打开即看到最新的，往下翻是更早的；轴从最近一次点亮的日期开始，距离与真实时间成比例（约每月 60px），每个已点亮的二级区域（及无二级的一级区域）一个分支，用缩小的首页方框显示名称和日期；同一天的多个区域里后点亮的在上面（按后台记录的点亮时刻；旧数据按编号）。 |
| 自定义框 | 无限层级；新建、重命名、类型（相册/美食/景点/餐厅/行程或自定义，不限制内容）、背景颜色（可选仅当前框 / 所在区域全部框及以后新建的框 / 整个网页）、排序（前移/后移）、移动（可跨区域）、提升一级、合并、复制为模板 / 粘贴、删除。 |
| 相册框 | 新建框时可选“相册框”：名称固定为“相册”，只能放照片，不能添加子框、备注或地点。照片超过 60 张时分批显示。支持多选：批量下载（iPhone 用系统分享面板“存储图像”，其他情况打包 zip）、批量删除。 |
| 框的规则 | 有子框的框不能放内容；有内容的末级框不能直接加子框，会提示“回到上一层新建一个框，再和它一起选中合并”。删除父框时子框提升一级；删除末级框时内容一起删除并进入回收记录（30 天内可恢复）。 |
| 照片 | 多选批量上传，单批最多 50 张；上传前读取 EXIF（拍摄时间、GPS、设备），再在浏览器端压缩为长边约 2560 的原图和长边约 400 的缩略图；整体进度与单张状态，失败项单独重试；不支持视频。HEIC 照片在浏览器无法直接解码时，按需加载解码组件。 |
| 大图 | 左右切换（支持滑动、方向键），统一的“⋯”菜单：查看属性、编辑说明、设为封面（可选所在框、上层框、二级/一级区域）、删除。读不到的属性显示“无可用信息”。 |
| 备注与地点 | 每个末级框可以有多条备注、多个地点，逐条添加、修改、删除。 |
| 地点 | 手动地址，或经授权读取当前位置（保存 WGS84 坐标，可取消定位）。配置腾讯位置服务 Key 后自动把坐标转成中文地址（Key 设置域名白名单）。只保留“在 Apple 地图中打开”（新页面打开，换算为 GCJ-02 坐标）和复制地址/坐标。 |
| 页面 | 明亮浅色主题（颜色集中在 `css/app.css` 顶部变量里，主色 #2f7cf6），毛玻璃顶栏与弹窗；照片封面先显示缩略图再换成清晰原图；手机上一行两个框，圆角与多层淡阴影；输入框字号 16px，避免 iPhone 自动放大导致左右滑动。同一标签页刷新不用重新输入密码。 |
| 登录 | 共享密码经 PBKDF2-SHA256（60 万次）派生密钥，用 AES-GCM 解开网页里的子账号密钥密文。密码错误提示“密码不正确，请重试”。“记住此设备”默认不勾选，勾选后在 IndexedDB 保存不可导出的解密密钥；菜单中“退出并清除本设备”。 |
| 两人使用 | 最多 2 台设备同时在线，第三台提示已满；点“开始编辑”取得编辑权，另一台只读，查看方每 20 秒自动同步。编辑权 2 分钟无续约自动失效；同一设备刷新页面后可直接收回自己的编辑权。保存前比对云端版本，版本变化时不覆盖并提示重新载入。 |
| 异常处理 | 保存失败有明确提示和“重试”；每次修改先在本机暂存草稿，崩溃或断网后下次取得编辑权时可恢复（前提是云端在此期间未被修改）。 |
| 维护工具 | `tools/admin.html`（使用维护子账号密钥）：上传区域名称与地图、回收记录恢复、清理过期记录、文件一致性检查、从历史版本恢复缺失文件、删除孤立文件、album.json 版本回退、清理旧在线记录。 |
| 加密工具 | `tools/encrypt.html`：在浏览器本地把子账号密钥和共享密码生成密文。 |

## 安全边界（方案 B，如实说明）

- 共享密码解开的是浏览器里的访问凭据，不是服务端身份认证。公开网页中的密文可能被拿去离线猜密码，所以共享密码要足够长。
- 在线人数限制和编辑权由网页自觉遵守（存放在 `meta/` 下的小文件），**不能**阻止有意绕过网页、直接用密钥读写存储桶的人，也不能在极端时序下严格保证同一时刻只有一人编辑。保存前的版本比对是防止互相覆盖的第二道保护。
- 网页用的子账号没有删除权限、不能改存储桶设置；删除操作只是从 `album.json` 中移除引用并写入回收记录，文件本身保留，过期后由维护工具清理。

## 云端文件结构

```
album.json            框架树、照片说明与属性、封面、回收记录
photos/{id}.jpg       压缩后的原图（长边约 2560）
thumbs/{id}.jpg       缩略图（长边约 400）
meta/lock.json        编辑权
meta/presence/*.json  在线心跳
meta/devices.json     在线设备登记
meta/region-names.json 区域简称（维护工具上传）
meta/china-map.json   清洗后的地图（维护工具上传）
```

## 分工

主界面的显示问题（颜色、字号、间距等，只改显示不改功能）默认由 Muse 处理，集中在 `css/app.css` 顶部的变量里修改；区域名称字号见其中的 `--name-*` 变量。

### 尚未验证（建议测试项）

以下项目在开发环境中无法执行，需上线后人工验收（步骤见部署说明第五部分）：

| 项目 | 原因 / 风险 |
|---|---|
| 真实 COS 读写、CORS、子账号权限 | 开发环境无法连接腾讯云；配置错误会导致“没有访问权限”。 |
| 编辑权与在线人数在真实网络下的表现 | 依赖 COS 的读写时延；极端时序下可能两人同时取得编辑权（版本比对仍可防覆盖）。 |
| 维护工具的历史版本列表、版本回退、从历史版本恢复文件 | 依赖存储桶开启版本控制，演示模式不支持。 |
| iPhone / 安卓真机上传与 EXIF | iOS 选图时可能已去除 GPS；微信转发的图片通常没有 EXIF。 |
| 电脑版 Chrome 上传 HEIC | 需要按需下载约 1.3MB 的解码组件，未在真机验证。 |
| Apple 地图定位是否偏移 | 链接中的坐标已换算为 GCJ-02，需在 iPhone 真机确认位置准确。 |
| 坐标转中文地址 | 需要腾讯位置服务 Key；域名白名单配合 JSONP 调用需上线后真机验证。 |
| github.io 在国内的访问速度 | 需实际使用观察。 |
| 时间线、修改点亮时间、多条备注/地点 | 真实名称与地图已由 Muse 上传并在线上核对（首页简称、地图着色正常）；地图横向展示、港澳小点在真机上的效果待验收；其余新功能尚待在 iPhone 真机上使用验收。 |
