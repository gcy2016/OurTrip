# 旅行相册

两人共用的网页版旅行相册：网页放在 GitHub Pages，照片和相册数据放在私有的腾讯云 COS 存储桶里。依据 `gcy2016/AI_Corp` issue #8《旅行相册 PRD 2.0》及其后的用户决定实现。

> 仓库名称约定：本仓库（网页代码，公开）与原 OurTrip 仓库（映射源文件，私有）互换名称——本仓库改名为 **OurTrip**，原 OurTrip 改名为 **workspace-9**。下文均按互换后的名称书写。

- 正式地址（开启 Pages 后）：`https://gcy2016.github.io/OurTrip/`
- 演示模式（不连接云端，数据只存在当前浏览器里，密码 `demo1234`）：`https://gcy2016.github.io/OurTrip/?demo=1`
- 部署步骤：[`docs/部署说明.md`](docs/部署说明.md)

## 功能概览

| 功能 | 说明 |
|---|---|
| 固定区域 | 一级 34 个、二级 333 个，完全来自 `data/region-map-anon.js`（与私有仓库 `workspace-9/private/region-map-anon.js` 相同，映射有变更时需同步复制）；第一版直接显示编号。没有二级区域的一级区域（A01、A02、A09、A22、A32、A33、A34）点进去直接是内容。 |
| 区域显示 | 名称、代表图片、默认颜色在 `js/region-display.js` 中维护。用户在网页上选的照片与仓库配置的代表图片“谁后设置谁生效”，可以互相替换；生效的一方失效时显示另一方，都没有时显示默认蓝色。 |
| 自动点亮 | 加载时由 `album.json` 计算：某区域下任意末级框里有照片、文字备注或地点，该区域及其一级区域就点亮；框标题和框结构不算。 |
| 自定义框 | 无限层级；新建、重命名、类型（相册/美食/景点/餐厅/行程或自定义，不限制内容）、背景颜色、排序（前移/后移）、移动（可跨区域）、提升一级、合并、复制为模板 / 粘贴、删除。 |
| 相册框 | 新建框时可选“相册框”：名称固定为“相册”，只能放照片，不能添加子框、备注或地点。照片超过 60 张时分批显示。 |
| 框的规则 | 有子框的框不能放内容；有内容的末级框不能直接加子框，会提示“回到上一层新建一个框，再和它一起选中合并”。删除父框时子框提升一级；删除末级框时内容一起删除并进入回收记录（30 天内可恢复）。 |
| 照片 | 多选批量上传，单批最多 50 张；上传前读取 EXIF（拍摄时间、GPS、设备），再在浏览器端压缩为长边约 2560 的原图和长边约 400 的缩略图；整体进度与单张状态，失败项单独重试；不支持视频。HEIC 照片在浏览器无法直接解码时，按需加载解码组件。 |
| 大图 | 左右切换（支持滑动、方向键），统一的“⋯”菜单：查看属性、编辑说明、设为封面（可选所在框、上层框、二级/一级区域）、删除。读不到的属性显示“无可用信息”。 |
| 地点 | 手动地址，或经授权读取当前位置（保存 WGS84 坐标，可取消定位）。配置腾讯位置服务 Key 后自动把坐标转成中文地址（Key 设置域名白名单）。只保留“在 Apple 地图中打开”（新页面打开，换算为 GCJ-02 坐标）和复制地址/坐标；地点可整体删除。 |
| 页面 | 手机上一行两个框，圆角与阴影；输入框字号 16px，避免 iPhone 自动放大导致左右滑动。同一标签页刷新不用重新输入密码。 |
| 登录 | 共享密码经 PBKDF2-SHA256（60 万次）派生密钥，用 AES-GCM 解开网页里的子账号密钥密文。密码错误提示“密码不正确，请重试”。“记住此设备”默认不勾选，勾选后在 IndexedDB 保存不可导出的解密密钥；菜单中“退出并清除本设备”。 |
| 两人使用 | 最多 2 台设备同时在线，第三台提示已满；点“开始编辑”取得编辑权，另一台只读，查看方每 20 秒自动同步。编辑权 2 分钟无续约自动失效；同一设备刷新页面后可直接收回自己的编辑权。保存前比对云端版本，版本变化时不覆盖并提示重新载入。 |
| 异常处理 | 保存失败有明确提示和“重试”；每次修改先在本机暂存草稿，崩溃或断网后下次取得编辑权时可恢复（前提是云端在此期间未被修改）。 |
| 维护工具 | `tools/admin.html`（使用维护子账号密钥）：回收记录恢复、清理过期记录、文件一致性检查、从历史版本恢复缺失文件、删除孤立文件、album.json 版本回退、清理旧在线记录。 |
| 加密工具 | `tools/encrypt.html`：在浏览器本地把子账号密钥和共享密码生成密文。 |

## 安全边界（方案 B，如实说明）

- 共享密码解开的是浏览器里的访问凭据，不是服务端身份认证。公开网页中的密文可能被拿去离线猜密码，所以共享密码要足够长。
- 在线人数限制和编辑权由网页自觉遵守（存放在 `meta/` 下的小文件），**不能**阻止有意绕过网页、直接用密钥读写存储桶的人，也不能在极端时序下严格保证同一时刻只有一人编辑。保存前的版本比对是防止互相覆盖的第二道保护。
- 网页用的子账号没有删除权限、不能改存储桶设置；删除操作只是从 `album.json` 中移除引用并写入回收记录，文件本身保留，过期后由维护工具清理。

## 云端文件结构

```
album.json            框架树、照片说明与属性、封面、回收记录
photos/{id}.jpg       压缩后的原图（长边约 2560）
thumbs/{id}.jpg       缩略图（长边约 400）
meta/lock.json        编辑权
meta/presence/*.json  在线心跳
```

```
index.html            相册页面
css/app.css
js/app.js             登录、路由、页面
js/album.js           数据模型（纯函数）
js/sync.js            album.json 读取与保存（版本比对、草稿）
js/session.js         在线人数与编辑权
js/store-cos.js       腾讯云 COS 读写
js/store-memory.js    演示/测试用存储
js/images.js          EXIF 读取与压缩
js/upload.js          批量上传面板
js/viewer.js          大图与照片菜单
js/boxes.js           框的编辑对话框
js/maps.js            地图链接
js/crypto.js          密钥加解密
js/config.js          存储桶、地域、密文（不含秘密）
js/region-display.js  区域名称、代表图片、默认颜色
data/region-map-anon.js
tools/encrypt.html    密钥加密工具
tools/admin.html      维护工具
cos/                  子账号权限策略、CORS、生命周期规则
vendor/               cos-js-sdk-v5、exifr、heic2any（MIT）
tests/                单元测试与端到端测试
```

网页无需构建，直接由 GitHub Pages 提供静态文件。

## 测试

```bash
npm test          # 单元测试（Node 18+）：区域映射、数据模型、加密、编辑权与在线、保存与冲突、地图链接
npm run e2e       # 端到端测试（需要 Playwright + Chromium），在演示模式下走通主要流程，含手机尺寸检查
```

端到端测试覆盖：登录与错误提示、区域导航、只读/编辑切换、批量上传（含视频拒绝、EXIF、2560/400 尺寸）、自动点亮、查看属性（有/无 EXIF）、照片说明、设为封面、有内容的框不能加子框、备注与地点、合并、复制粘贴、跨区域移动、删除（父框/末级框/取消）、保存失败重试、上传失败重试、第二人只读、第三人被拒、编辑权交接、版本冲突、“记住此设备”、手机尺寸、维护工具恢复、加密工具。

### 尚未验证（建议测试项）

以下项目在开发环境中无法执行，需上线后人工验收（步骤见部署说明第五部分）：

| 项目 | 原因 / 风险 |
|---|---|
| 真实 COS 读写、CORS、子账号权限 | 开发环境无法连接腾讯云；配置错误会导致“没有访问权限”。 |
| 编辑权与在线人数在真实网络下的表现 | 依赖 COS 的读写时延；极端时序下可能两人同时取得编辑权（版本比对仍可防覆盖）。 |
| 维护工具的历史版本列表、版本回退、从历史版本恢复文件 | 依赖存储桶开启版本控制，演示模式不支持。 |
| iPhone / 安卓真机上传与 EXIF | iOS 选图时可能已去除 GPS；微信转发的图片通常没有 EXIF。 |
| 电脑版 Chrome 上传 HEIC | 需要按需下载约 1.3MB 的解码组件，未在真机验证。 |
| Apple 地图定位是否偏移 | 链接中的坐标已换算为 GCJ-02，需在 iPhone 真机确认位置准确。 |
| 坐标转中文地址 | 需要腾讯位置服务 Key；域名白名单配合 JSONP 调用需上线后真机验证。 |
| github.io 在国内的访问速度 | 需实际使用观察。 |
